## The decision (Ryan + James, 2026-09-08)
Anvil 2.0 is a standalone, self-contained platform (own backend, frontend, API, orchestration) so it can be cloud-hosted and SOC 2-audited later. Simplest, most reliable, modern implementation. Collectors reimplemented as a modern check framework (run one control, one source, or the whole stack). No ephemeral Windows VMs, no console passthrough. AD via Action1-run PowerShell on a DC or the existing run package.

## Stack (v1.0)
web (React+TS+Vite, shadcn, generated OpenAPI client) · api (FastAPI, Pydantic v2, SQLAlchemy 2, Alembic) · worker (checks, evaluation, renderers) · PostgreSQL 16 as the ONLY database (app state, evidence index, evaluations, Postgres-backed job queue + cron schedules, audit log) · S3-compatible object store with object lock (MinIO on VM, S3 in cloud) · OIDC to Entra ID · Bitwarden Secrets behind a SecretsProvider interface · containers + Compose on one VM per env · Grafana reads Postgres views, alerts to PagerDuty · GitHub Actions CI, signed images + SBOM. Retired: ClickHouse (analytics export only), Redis/broker/Dagster, ephemeral runners, PVE-Ansible engine roles for Anvil internals. Kept: credential vault, evaluation service, Blacksmith staging package, all 1.x contracts (evidence tree, manifests, matrix, prompt v2.4/schema v2.3, renderers, runbook).

## Collector framework v2
Check = evidence id + CSF control + credential slots/scopes + kind (inventory/sample, 1.x cap policy) + function. Source = package of checks + auth adapter. Run = selection (check / control / source / full stack / scheduled) producing the exact 1.x run directory. `evidence_latest` view = newest successful item per (client, evidence id). Guarantees: contract tests vs 1.x fixtures, read-only HTTP client (GET-only except allow-listed POST-for-read), secret redaction, mock mode, versions in manifest. Port order S1 → Duo → Action1 → Mimecast → Meraki → Auvik → Umbrella → KB4 → GWS → M365 → AD; ~24 builder-days + parity runs (manifest diff vs 1.x = ship gate).

## AD channel
A (primary): Action1 automation runs the signed Collect-ADGPEvidence script on the DC (SYSTEM); script POSTs hashed zip to Anvil ingest endpoint with one-time token; state polled via Action1 API. B (fallback): run package + portal upload or self-push. Guardrails: hash-pinned script per release, single-use tokens tied to an open AD job, manifest verification, no credentials in script.
